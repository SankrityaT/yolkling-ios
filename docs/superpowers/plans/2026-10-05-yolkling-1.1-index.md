## Production safety, every plan that touches Supabase

Project `vlucekvrdxvpkvbizabz` is live with real players. These rules hold for every
database change in 1.1:

1. **Additive only.** New tables, new functions, new indexes. No `drop`, no `alter table
   ... drop column`, no `create or replace` of an existing function, no change to an
   existing row's meaning. If an existing function must change, it gets a new name
   (`_v2`), the way `push_wallet_v2` did.
2. **One new file per plan in `docs/sql/`**, idempotent (`create table if not exists`,
   `create or replace function` for the plan's own new functions only), and appended to
   the order list in `docs/sql/README.md` **before** `auth_identity.sql` and
   `auth_enforce.sql`, which always run last.
3. **Every new function derives the caller from the session.** It calls `public.me()`
   and takes no `p_user` parameter, so there is nothing for a client to spoof.
   `security definer`, `set search_path = public`, and an explicit
   `grant execute ... to authenticated`.
4. **Tested on a throwaway local Postgres before production**, with the harness in plan
   2, task 1. The production apply never happens with a red local run.
5. **Applied in one transaction** through the management API, then verified with
   read-only queries. A fresh access token is needed: the one in
   `/Users/sankiii/yolkling-app/.env.local` returned "Unauthorized" on 2026-10-05.
6. **Never pasted, printed or committed:** access tokens, the database password, the
   service role key.

## Product rules every plan keeps

- Eggs, packs and every random reveal are earned only. Bought Yolks never buy anything
  random.
- Trading is friends only and is a swap. No Yolks change hands in a trade.
- No species and no wellbeing feature is ever paid.
- Copy is lowercase, calm, no exclamation marks, no em dashes.
